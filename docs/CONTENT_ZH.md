## 小红书：开发者实践版

### 标题候选

- 会议纪要一定要上云吗？我做了个本地优先的桌面工具
- 做会议转写工具后，我先想清楚了“哪些数据会离开电脑”
- 不想把会议内容交给云服务？这是我在做的本地工作流

### 正文

我一直在想一个很实际的问题：会议录音和转写文本，是否一定要上传到云端才能整理？

所以我在做 PanNote，一个本地优先的桌面工作台，尝试把录音、转写、笔记和纪要整理放在自己的电脑上完成。它目前还是 macOS 开发预览版，安装和模型配置还不够轻松，Windows/Linux 版本也还没有准备好。

我也不想只用一句“数据不出本机”带过：当前版本的数据库没有应用层加密；主动使用联网搜索时，搜索词会发送给搜索服务；如果把 Ollama 配到非本机地址，提示内容也可能发往那台服务。云端大模型回退目前是规划中的能力，不应该在未经说明和同意的情况下开启。

现在我更想找少量愿意认真试用的技术用户，看看真实卡点是安装、模型速度，还是纪要整理本身。请用合成或明确获准的音频测试，不要拿涉密/工作资料试用。

项目状态和隐私说明：**[填写公开 GitHub 地址]**

如果你对“会议内容本地处理”有真实需求，欢迎告诉我你最在意的一个点：安装门槛、识别效果、纪要质量，还是隐私边界？

### 发布检查

- 不带真实会议截图、录音波形中的敏感标题、数据库界面、人员姓名或单位标识。
- 不写“财务部已部署/单位内部使用/涉密可用”，除非取得明确书面授权并经法务/合规确认。
- 不写“绝对离线”“零数据外发”“军工级安全”“符合某法规”等未验证承诺。
- 页面要明确标注开发预览状态和当前安装要求。

## 知乎：长文题目与摘要

### 题目

**会议纪要必须依赖云端 AI 吗？我做本地优先工具时遇到的取舍**

### 摘要

我在开发 PanNote，一个 macOS 优先的会议转写与笔记工具。本文不把“本地”当作万能安全标签，而是拆解本地模型、联网搜索、端点配置、数据库保护和安装信任之间的区别。当前版本仍是开发预览，不能替代机构安全评估，也不建议用于涉密或受监管数据。

### 正文结构

1. 为什么会议录音/转写文本值得先讨论数据流。
2. “本地转写”“本地 LLM”“本地保存”分别意味着什么。
3. 哪些动作仍可能访问网络：用户触发搜索、非本机 Ollama 地址、未来的显式云端功能。
4. 为什么本地 SQLite 未加密，不能简化成“数据绝对安全”。
5. 当前 macOS 开发预览的安装限制和测试范围。
6. 接下来要解决的事情：一键安装、模型许可、签名、公证、Windows/Linux 验收。
7. 邀请用户反馈，但只接受合成或已授权的测试材料。

## 发布节奏建议

- 第 3 篇：有稳定公开版本后，再发布体验邀请和安装链接。
